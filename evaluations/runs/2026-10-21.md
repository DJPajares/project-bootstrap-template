# Structured workflow repair — 2026-10-21

## Problem and scope

A real generated-project comparison exposed a regression: the agent guide flattened a mature operating structure into prose, the Claude bridge was absent, and task drafting no longer retained the model/manual-check fields and completion format. Earlier evaluation emphasized short output and broad safety boundaries; it did not establish fidelity to the source operating rules. The previous report remains historical evidence, not validation of this repair.

This change repairs the bootstrap only. The reported project and its task records were inspected read-only; they were not modified. No private project text, names, destinations, or task contents are included in the synthetic cases or controlled model inputs retained here.

## Source-rule coverage

| Reusable source pattern                              | Required destination and treatment                                                                                                                                                                                  |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Product authority versus task/implementation status  | Project section in AGENTS; one owner per record; proposals and observed evidence remain distinct.                                                                                                                   |
| Scope discipline and established project conventions | Working Rules as individual bullets, with actual target boundaries rather than renamed source-domain rules.                                                                                                         |
| Technical direction and architecture                 | Separate applicable sections; preserve selected stack and actual ownership, relationship, permission, recovery, and resource contracts. No source providers, technologies, or domain features become defaults.      |
| Direct chat versus issue-backed work                 | Separate Task Workflow paths; no forced issue creation or repeated brainstorming for a direct implementation request.                                                                                               |
| Numbered task delivery loop                          | Read blockers; inspect branch; enter active state; targeted reads; implement scope; validate; self-review; commit/push/review/link; enter review; identify approved next work if applicable; stop for human review. |
| Tracker and repository conventions                   | Mandatory when selected; resolve actual scope, states, supplied branch names, linking behavior, and completion event. No universal service names or guessed automation.                                             |
| Executable task fields                               | Description, Scope, Suggested Models & Reasoning, Acceptance Criteria, Dependencies, Execution Context and Verification; Manual Test when meaningful. Separate task reference and pre-publication quality checks.   |
| Current / Next response                              | Required issue-backed completion format with actual review/task links, validation, model/effort, and reason. Direct chat completions remain brief without invented backlog work.                                    |
| Branch/review control                                | Check before first edit and every commit/push; protect the integration branch; human review; no automatic merge or premature completion.                                                                            |
| User notes/version policy                            | Apply to relevant products; classify visible work in the same change, preserve history, use actual formats/versioned units and checks. No transplanted catalogs or package paths.                                   |
| Focused/runtime validation                           | Testing section with actual commands, meaningful tests/manual checks, evidence gaps, and separation of document review from runtime proof.                                                                          |
| Human authority/context efficiency                   | Explicit sections; autonomy for routine authorized work, focused reads, no duplicate specifications/backlog mirrors.                                                                                                |
| Agent compatibility                                  | Required CLAUDE.md with an unfenced @AGENTS.md import; one canonical shared rule set; preserve tool-specific additions without circular imports.                                                                    |

The [Claude Code memory documentation](https://code.claude.com/docs/en/memory#share-one-file-with-other-coding-tools) supports the import bridge. A sentence merely asking the model to read another file is not the same import mechanism.

The omitted testing policy prompted a rule-by-rule check, not just a heading check. The file-only fixture's wording was clarified from “Give me the files only” to “Use file delivery” so it selects a route without imposing a conflicting response-format restriction. Instructions also clarify the route/format distinction and require consistency between safety boundaries and proposed mechanisms. Earlier failures remain visible; the final result does not establish that every model will interpret the ambiguous wording identically. The planning case's consumed instruction/task-reference files were unchanged by these later bootstrap edits.

Structural checks parsed the actual generated file contents: standalone unfenced import, no unresolved authoring placeholders or template-relative links, required rule/task/completion sections, numbered execution, preserved fixture states and Claude addition. Qualitative review separately assessed actual behavior, boundaries, readiness, model honesty and manual steps. The synthetic task is specific enough to execute and avoids the repeated global-policy padding seen in the reported output.

Static checks pass for Markdown/JSON formatting, source-rule/schema coverage, placeholders, local/canonical links, unchanged entry prompts, candidate/response fingerprints, and whitespace. All 11 fixtures received an instruction walkthrough; only the three scenario types above received model runs in this repair. No other fixture is claimed model-passed. Detailed technical proposals in generated product plans remain proposals and were not implemented or runtime-verified.

## Limits

These checks do not prove every platform loads the files or that an agent performs real issue/repository transitions correctly. Actual Claude session loading, connected-service behavior, and broader usability coverage remain separate checks. Existing 2026-10-20 records are preserved with their original source fingerprints and limitations. No model run is a user study or application implementation test.
