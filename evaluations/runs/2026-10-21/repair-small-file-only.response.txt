The recommended first version is a deliberately conservative, single-folder utility: preview a deterministic rename plan by default, apply it only with an explicit flag, and abort before changing anything if a destination already exists or two files would receive the same name. It handles regular files only and does not recurse.

The exact cleanup convention remains a proposed decision. The documents recommend trimming surrounding whitespace from filename stems and converting internal whitespace runs to single hyphens while preserving extensions. The program itself is not included.

## Purpose and scope

SafeName Preview is a small Python utility for people who want to clean up filenames in one folder without accepting an opaque or destructive bulk rename.

The utility examines one explicitly selected folder, builds a complete proposed rename plan, and displays that plan without changing files. Renaming occurs only when the user makes a separate invocation with an explicit apply option.

- **First useful result:** A standard-library-only Python utility that previews and, when explicitly requested, applies safe filename cleanup to eligible files directly inside one folder.
- **Outside this version:** Recursive traversal, directory renaming, symbolic-link handling, undo history, configuration files, interactive prompts, graphical or web interfaces, servers, databases, external services, trackers, background watching, and automatic execution.
- **Success evidence:** Representative temporary-folder tests show deterministic previews, no changes during preview, explicit application of the displayed plan, preservation of file contents, and refusal to overwrite or create ambiguous destinations.
- **Tradeoff principles:**
  - Prefer refusing a rename over risking data loss.
  - Keep preview and apply behavior consistent and understandable.
  - Keep the first version narrow enough to inspect and test thoroughly.
  - Use only the Python standard library.

## Users and primary workflow

The intended user is someone comfortable running a local Python command who wants a safe view of proposed filename changes before accepting them.

The shortest useful workflow is:

1. The user invokes the utility with one folder path.
2. The utility examines eligible files immediately inside that folder.
3. It displays each proposed source and destination name, along with skipped files and blocking conflicts.
4. Preview exits without modifying the folder.
5. The user reviews the output.
6. The user repeats the invocation with an explicit apply option.
7. The utility rebuilds and validates the plan against the folder's current state.
8. It either applies the valid plan or refuses to begin when a conflict or unsafe condition is present.
9. It reports every completed, skipped, blocked, or failed operation truthfully.

A previous preview is informative rather than authorization. Apply must use the current folder state and must not assume that an earlier preview remains valid.

## Filename and safety rules

The following rules are recommended for the first version and require owner approval before implementation:

- Work from the filename, not the full path.
- Preserve a recognized final extension while cleaning only the stem.
- Trim surrounding whitespace from the stem.
- Replace every remaining run of whitespace in the stem with one ASCII hyphen.
- Leave other characters unchanged.
- Skip a file when cleanup produces its existing name.
- Reject a result with an empty stem.
- Treat case-only changes as unsupported until behavior is defined and tested for the target operating systems.
- Do not attempt to sanitize every operating system's reserved names in this version. Detect and report a destination rejected by the active platform.
- Sort plans by source name for deterministic output.

Extension parsing for leading-dot files and names with trailing whitespace is a material edge case. The recommended rule is to treat a name beginning with a single dot and containing no other dot as having no extension, but this remains part of the cleanup-policy approval gate.

- `PRD.md` — approved product behavior and scope.
- `AGENTS.md` — execution and validation rules.
- `CLAUDE.md` — one-way import of the canonical agent rules.

Technical constraints:

- Use Python and its standard library only.
- Do not add third-party runtime or development dependencies.
- Keep filename transformation separate from filesystem planning and mutation so it can be tested as a deterministic function.
- Keep plan validation separate from apply.
- Centralize filesystem mutation in a small boundary that enforces no-clobber behavior.
- Do not introduce persistent state, a manifest database, configuration system, network access, or telemetry.
- Avoid claiming cross-platform safety until no-overwrite behavior has been tested on each supported operating system.

Proposed invocation shape:

- `python -m safename_preview FOLDER` for preview.
- `python -m safename_preview FOLDER --apply` for explicit application.

These commands describe the intended future interface. They have not been implemented or executed, and the final module layout may require a grounded adjustment.
