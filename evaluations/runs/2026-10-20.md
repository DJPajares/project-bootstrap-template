## Findings and changes

The preliminary novice response gave audience/problem direction, bounded scope, exclusions, assumptions, and one delivery choice before setup. The missing-access response distinguished an unconnected GitHub integration from verified creation capability and deferred the tracker. These observations support the first-value and access-disclosure rules within the mocked environment; they do not prove a real integration works.

Full-file responses exposed two concrete defects: nested Markdown fences made copying awkward, and the large default outline encouraged repetition in a small project. The instructions now require safe outer fences and a planning starter with the resolved planning URL. The templates now begin with a compact core and retain detailed contracts as conditional authoring modules. A later sample improved formatting and the handoff but remained too long; this prompted explicit default word budgets and a rule against prescribing unrequested technical mechanisms. Safety and existing contracts can justify additional depth.

The engineer fixture originally asked for “file contents only,” which could reasonably exclude a separate handoff. That wording was clarified to select file delivery without forbidding the handoff; the original response remains available. The preliminary harness also named source files without their canonical URLs and omitted the linked planning source. Later bootstrap runs supplied the canonical source URLs and planning text. Because inputs and instructions both changed, the observations are not a controlled causal comparison of a single wording change.
